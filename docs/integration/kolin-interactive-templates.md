# Kolin interactive templates

In the private teacher chat, select **Интерактив / Interaktiv** and request a graph, triangle or fraction circle for a named pupil. A private read-only preview appears first. Only **Добавить [имя] / Für [Name] hinzufügen** appends it to that pupil's workbook. One object is generated by default, at most five per request.

Open the object from its workbook page. Teacher and admitted pupil can change its parameters. The graph supports linear and quadratic coefficients from -10 to 10. Triangle vertices stay within [-5, 5] and cannot become degenerate. Fraction circles contain 2 to 24 sectors. No model requests run when moving controls. A short model request selects the template and numeric parameters; the existing Kolin context and transport are reused.

The editor opens in a modal so ordinary board drawing and two-finger scrolling retain their existing gestures. The initial version supports these three template families, not arbitrary geometry. The model does not read workbook handwriting. The saved transcript continues to be used on teacher requests.

## Persistence and privacy

Drafts reuse `kolin_worksheets` with result type `interactive` and validated canonical task content. No database migration is needed. Confirmation transactionally appends blank PDF pages, teacher-owned annotation objects and the durable receipt; repeated confirmation returns the existing receipt. Original PDF pages and annotation documents are preserved.

Objects live in personal workbook annotation documents. Existing admission and ownership checks restrict access to the host and the named pupil. Updates include the last accepted operation ID and are serialized under the document lock. A concurrent stale edit is rejected and the editor asks to reopen. No arbitrary JavaScript, SVG or HTML is accepted. Number bounds and the template family are checked on the server.

The board's PDF export includes the current rendered object and annotations. The underlying workbook PDF alone contains the page backgrounds; interactive parameters live in the annotation log.

## Verification

- `InteractiveTemplateSpecTest`: closed schemas, numeric limits and revision payloads.
- `KolinOpenAiPayloadTest`: one structured request, no attachments, compact interactive prompt and 2500-token output ceiling.
- `KolinTaskServiceTest`: private draft with no PDF renderer or automatic append.
- `KolinWorkbookAppendIntegrationTest`: real PostgreSQL, confirmation idempotency, teacher/pupil replay, stale and concurrent edits, access restrictions and atomic rollback.
- Frontend tests cover independent mathematics, strict parsing, controls, revisions, read-only previews and confirmation.
- `node e2e/interactive-start-vite.mjs` serves `/e2e/interactive-templates.html` locally on port 4185. This visual fixture shares state in memory between teacher/pupil views; server persistence is covered separately by integration tests.

Before production release, run CI and obtain the owner's approval. After deployment, verify generation, explicit append, reconnect and PDF export in a separate synthetic lesson.
