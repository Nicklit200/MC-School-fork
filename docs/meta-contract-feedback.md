# Mindcrafti: передача подписанных договоров в Meta

Это **Mindcrafti School**, НЕ MyDomm. Используется Meta Pixel / Dataset ID **1391828005920802** из `mindcrafti-school/app/meta-pixel.tsx`.

## Что реализовано (в отдельной ветке, не в production)

- В `/admin/leads` уже есть этап `CONTRACT` («Контракт»).
- Только в статусе `CONTRACT` администратор может явно нажать «Передать подписанный договор в Meta».
- Обязательны реальная дата подписания и подтверждение документированного законного основания.
- Событие: `ContractSigned`, источник `system_generated`, `event_source: crm`.
- CAPI: `POST https://graph.facebook.com/v26.0/1391828005920802/events`.
- В Meta передаётся **SHA-256 хеш телефона родителя**, а не сам номер, ответы про ребёнка, школа, класс, доход, диагноз или посещаемость.
- Уникальная пара `lead_id + event_name` и стабильный `event_id`: повторные клики не создают новые продажи.
- Таблица аудита `trial_lead_meta_conversions` содержит статус `SENDING / TEST_SENT / SENT / FAILED`, время и подтверждение правового основания.
- События с фактической датой старше 7 дней не отправляются. Не меняйте реальную дату на сегодняшнюю.
- При отсутствии ключа CAPI сервер отказывает (503), не имитирует успешную отправку.
- Без явного подтверждения и нажатия кнопки никакие данные не передаются Meta.

## Перед активацией

1. **Обязательная проверка GDPR**. На `mindcrafti.de/de/datenschutz` сейчас написано, что Meta Pixel не используется, но в `mindcrafti-school/app/meta-pixel.tsx` Pixel **1391828005920802** загружается без предварительного выбора. Это несоответствие надо устранить, настроить согласие и актуализировать Datenschutzerklärung **до отправки новых персональных данных в Meta**. Даже SHA-256 номера — персональные данные при сопоставлении.
2. Убедитесь, что используемая продакшен-админка действительно развернута из `MC-School-fork` и найдите её живую production-ветку. Эта реализация сейчас находится только в `feature/mindcrafti-meta-contract-feedback`, созданной от `test/online-classes-staging`. Не сливайте в production вслепую.
3. После проверки PR и тестов разверните интеграцию. Flyway выполнит `V56__create_trial_lead_meta_conversions.sql` автоматически.
4. В Meta Events Manager выберите именно **Mindcrafti**, не `MyDomm_Pixel`; получите ключ Conversions API для Dataset ID 1391828005920802.
5. Добавьте `META_CAPI_ACCESS_TOKEN` в **Railway → API service → Variables** как секрет. Не отправляйте ключ в чат и не добавляйте в GitHub.
6. Для тестов можно временно задать `META_CAPI_TEST_EVENT_CODE`, получить код во вкладке Test Events. Отправки с этим кодом получат статус `TEST_SENT`, а не `SENT`. После проверки удалите тестовый код и отправляйте настоящие события при наличии основания.
7. В CRM найдите каждого подписавшего: `Продажи → Заявки на пробный урок`, статус `Контракт`, заполните **фактическую дату** подписания, подтвердите основание и отправьте в Meta. Повторно сделка не учитывается.

## Уже подписанные два клиента

Нужно проверить:
- оба ли клиента **есть** в CRM и связаны с той же рекламной воронкой;
- фактические даты двух договоров (не дата ввода в CRM);
- есть ли документированное законное основание для передачи контактной информации родителей рекламной платформе.

Клиентов вне CRM нельзя выдавать за заявки воронки. Если договорам больше 7 дней, не отправляйте их через CAPI с вымышленной датой: сохраните реальные сделки в учёте и используйте дальнейшие договоры для обучения Meta.

## Оптимизация

Событие `ContractSigned` является пользовательским, потребуется создать **Custom Conversion** в Events Manager (если Meta не предлагает выбрать его прямо). **Два события — слишком мало**, чтобы алгоритм стабильно оптимизировал показы по договорам; пока лучше продолжать оптимизацию по `Lead` и собирать фактическую обратную связь.

Не путайте с `MyDomm_Pixel` (**2506842576471727**): эта интеграция не отправляет ничего в MyDomm.
